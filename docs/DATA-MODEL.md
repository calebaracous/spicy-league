# Data model

All schemas live in `src/db/schema/` — one file per domain, re-exported from
`src/db/schema/index.ts`. The Drizzle client is `src/db/client.ts` (Neon
`Pool` over WebSocket via `drizzle-orm/neon-serverless`, so
`db.transaction()` and `SELECT … FOR UPDATE` work) and uses **snake_case**
column naming (`casing: "snake_case"` in both
`drizzle.config.ts` and `client.ts`). IDs are all `text` primary keys —
either crypto.randomUUID() (`$defaultFn`) or string IDs supplied by Better
Auth.

## Migrations

`drizzle/` holds a **squashed** history (the old `0000_init` … `0010`
files are in git history before the squash commit):

- `0000_baseline.sql` — the whole schema, generated by `drizzle-kit
  generate` from `src/db/schema` against an empty history, plus the
  hand-written `ten_mans_active_uniq` partial unique index at the bottom.
  The index is deliberately **not** in the snapshot, so `db:generate`
  never tries to drop it.
- `0001_reconcile_live_schema.sql` — idempotent. A no-op on a DB built
  from the baseline. On a DB that ran the old history (production), it
  makes `ten_mans.created_by` nullable, re-creates 10 user FKs under
  Drizzle's default names with the intended `ON DELETE` actions, ensures
  the partial index exists, and backfills `seasons.champion_team_id`.

- `0002_user_bans.sql` — adds the four nullable ban columns to `users`.
- `0003_match_substitutions.sql` — `substitution_status` enum + `match_substitutions`.
- `0004_sub_signups.sql` — `signup_kind` enum + `season_signups.kind`.
- `0005_season_schedule.sql` — `seasons.draft_at`, `group_stage_ends_at`, `semis_at`, `final_at`.
- `0006_signup_quandary.sql` — nullable `season_signups.quandary`.
- `0007_group_bo2.sql` — `seasons.group_best_of` (int, default 1) and
  `tiebreaker` added to the `match_stage` enum.
- `0008_discord_username.sql` — nullable, unique `users.discord_username`.
- `0009_discord_roles.sql` — `users.discord_user_id`, `teams.discord_role_id`.
- `0010_discord_team_channels.sql` — `teams.discord_text_channel_id`,
  `teams.discord_voice_channel_id`, `seasons.discord_category_id`.

**Why the baseline's `when` is old.** Drizzle's migrator applies a journal
entry only if its `when` is greater than the newest `created_at` in
`drizzle.__drizzle_migrations`. The baseline is pinned to `1777163682000`,
just under the old `0007` row (`1777163682691`) — the newest row
production has. So production (and any DB that ran the old history)
skips the baseline and only runs `0001`; a fresh DB runs both. Every
future migration gets a normal, current timestamp. **Don't change the
baseline's `when`.**

Workflow:
- Fresh DB: `npm run db:migrate` (reads `DATABASE_URL` from `.env.local`
  via `drizzle.config.ts`). Don't use `db:push` — it can't create the
  partial index.
- Schema change: edit `src/db/schema/*`, `npm run db:generate`, review the
  SQL, `npm run db:migrate`. Never edit an applied migration.
- Something Drizzle can't express (partial/expression indexes, data
  backfills): `npx drizzle-kit generate --custom --name <name>` and write
  the SQL by hand.

## auth.ts — users, sessions, accounts, verifications

These four tables are **Better Auth's required shape**. Don't rename
columns. Better Auth's `drizzleAdapter` expects exactly this schema (see
wiring in `src/lib/auth.ts`).

### `users`
- `id` text PK (Better Auth–supplied)
- `email` unique, not null
- `emailVerified` bool — set by Better Auth after verification link clicked
- `name` — Better Auth standard field used as the **editable display name**
  (shown in draft lists, rosters, captains page). Defaults to username at
  signup. 1–50 chars, editable on `/profile`.
- `image` — Better Auth standard field (unused in UI)
- **Custom fields** (added via `additionalFields` in `src/lib/auth.ts`):
  - `username` text **unique** — immutable handle set at signup; the
    sign-in identifier and the public URL slug at `/users/{username}`.
    (Renamed from `display_name` before the migration squash.) Regex: `[a-zA-Z0-9_-]{3,24}`.
    `input: false` means clients cannot set it via Better Auth's endpoints.
  - `role` enum `user_role` (`user | admin`), default `user`
  - `bio`, `pronouns`, `opggUrl` — free-text profile fields. `opggUrl` is an
    optional *custom* link (e.g. a multi-search); every Riot link already gets
    a derived OP.GG link (`opggUrlForRiotId`, `src/lib/opgg.ts`).
  - `discordUsername` text **unique**, nullable (migration
    `0008_discord_username`) — stored normalized (lowercase, no `@`) by
    `normalizeDiscordUsername` in `src/lib/discord.ts`, so the plain unique
    constraint is effectively case-insensitive. Required at account signup
    and for season signups; null on accounts made before it existed.
  - `discordUserId` text, nullable (migration `0009_discord_roles`) — Discord's
    numeric ID, resolved from `discordUsername` by the first role sync and
    cleared when the username changes or Discord reports them gone. See
    [DISCORD.md](DISCORD.md).
  - `bannedAt`, `banReason`, `banExpiresAt`, `bannedBy` — league ban
    (migration `0002_user_bans`). Active while `bannedAt` is set and
    `banExpiresAt` is null or in the future (`isBanActive` in
    `src/lib/bans.ts`). Expired bans are left in place, just inactive.
- `createdAt`, `updatedAt` — auto-defaulted

### `sessions`
- `token` unique — cookie value lives here
- `userId` FK → users, cascade delete
- `expiresAt`, `ipAddress`, `userAgent` — Better Auth bookkeeping

### `accounts`
Despite the name, this is **not** OAuth accounts — Better Auth stores
hashed passwords for email+password auth here (`password` column). One row
per (user, provider). For our setup provider is always `"credential"`.

### `verifications`
Token storage for email verification and password reset. Polled by Better
Auth, not queried directly by app code.

## seasons.ts — seasons, signups, captains

### `seasons`
- `id`, `name` (unique), `slug` (unique, validated)
- `game` enum `game` = `lol | cs2`
- `state` enum `season_state` — eight values; see
  [SEASON-LIFECYCLE.md](SEASON-LIFECYCLE.md) for the state machine
- `description` (text), `rules` (text) — markdown-ish, rendered as
  `whitespace-pre-wrap`
- `signupOpensAt`, `signupClosesAt`, `seasonStartAt` — optional timestamps
- `draftAt`, `groupStageEndsAt`, `semisAt`, `finalAt` — optional schedule
  timestamps (migration `0005_season_schedule`). `seasonStartAt` doubles as
  the group stage start. Display only — nothing gates on them, and they don't
  set `matches.scheduledAt`. `seasonSchedule()` in `src/lib/seasons.ts` turns
  them into the ordered "key dates" list used by the season page and the
  upcoming home section; edited in the admin season form.
- `groupBestOf` int, default 1 (migration `0007_group_bo2`) — group-stage
  series length: 1 = report a winner (+ optional score), 2 = Bo2 series
  reported as 2–0 / 1–1 / 0–2 where 1–1 is a draw. Edited in the admin
  season form (`GROUP_BEST_OF_OPTIONS`). See [MATCHES.md](MATCHES.md) →
  Group format.
- `discordCategoryId` (migration `0010`) — Discord category holding the
  season's team channels, created by `syncTeamRoles`.
- `championTeamId` — set by `confirmMatch` when the **final** is
  confirmed (to the final's `winnerTeamId`), cleared again if that final
  is disputed or reset. Migration `0001_reconcile_live_schema` backfilled
  it for seasons that already had a confirmed final. Read by `src/lib/homepage.ts`
  (past-seasons strip, off-season podium). No FK to `teams`.
  `src/app/seasons/[slug]/page.tsx` still derives the champion from the
  final match directly; both agree as long as the final goes through
  `confirmMatch`.
- `createdBy` FK → users (set null)
- Index on `state` for the home-page live-season query

### `seasonSignups`
One row per (season, user). Enforced by a unique constraint
`season_signups_season_user_uniq`.

- `rolePrefs` jsonb — shape depends on game:
  - LoL: `{ primaryRole, secondaryRole }` (one of `top | jungle | mid | adc | support | fill`)
  - CS2: `{ mapPrefs: [...] }` (subset of 7 map strings)
  - Schema lives in the server action: `src/app/seasons/[slug]/signup/actions.ts`
- `notes` — free text (for subs: when they're available)
- `quandary` — free-text answer to the signup form's moral quandary (`SIGNUP_QUANDARY` in
  `src/lib/seasons.ts`; migration `0006_signup_quandary`). Shown wherever `notes` is: admin
  signups table, CSV export, Teams page subs list. Required on new signups
  (`submitSignup`); the column stays nullable because older rows predate it.
- `kind` enum `signup_kind` (`player | sub`, default `player`; migration
  `0004_sub_signups`). `sub` = chose "Sub only" on the signup form, or joined after regular
  signups closed (`resolveSignupKind`) — excluded
  from the draft pool (`getDraftSnapshot`, `startDraft`, `submitPick`),
  captain promotion and signup counts. Every query that means "draft pool"
  must filter `kind = 'player'`.
- Cascade delete from season or user

### `seasonCaptains`
One row per (season, user) — unique. `captainOrder` is 1-indexed and drives
the snake draft. **Two rows sharing a `captainOrder` are duo captains of one
team** (no extra column; `groupCaptainTeams` in `src/lib/draft.ts`). The
first-promoted (`createdAt`) is the team's primary. Mutated via
`promoteCaptain` / `demoteCaptain` / `moveCaptain` / `pairCaptain` /
`splitCaptain` in `src/app/admin/seasons/[slug]/signups/actions.ts`, which
keep orders contiguous with `renumberCaptains` (duos stay on one number).
There is deliberately **no** unique constraint on `(seasonId, captainOrder)`
— adding one would make duos impossible. `moveCaptain` swaps through a `-1`
placeholder (three writes).

## drafts.ts — drafts, picks, teams, team_members

### `drafts`
One-to-one with seasons (`seasonId` has `unique`). `state` enum `draft_state`:
- `pending` — row exists but not started
- `in_progress` — server actions accept picks
- `paused` — admin-paused; `submitPick` rejects
- `completed` — set by `finalizeDraft()` when last pick lands

### `draftPicks`
- `pickNumber` — global 1-indexed; two unique constraints:
  - `(draftId, pickNumber)` — no duplicate pick slots
  - `(draftId, pickedUserId)` — a user can't be picked twice
- `captainUserId`, `pickedUserId` — both FK → users

Snake math: see `snakeOrder` / `teamForPick` in `src/lib/draft.ts`. Every
team ends up with `TEAM_SIZE = 5` players: a solo captain + 4 picks, or duo
captains + 3 picks.

### `teams`, `teamMembers`
Created in one batch by `finalizeDraft()` in `src/lib/draft.ts` once all
picks are in. `teams.discordRoleId` (migration `0009_discord_roles`) is the
team's Discord role, set by `syncTeamRoles` and cleared when a later season's
sync deletes it; `discordTextChannelId` / `discordVoiceChannelId` (migration
`0010`) are its private channels. `teams.name` starts as "Team <captain>"
and captains can rename it (`renameTeam`, rules in `src/lib/team-name.ts`;
unique per season, case-insensitive, enforced in code). `teamMembers.pickNumber` is `null` for the captain's own row,
otherwise it mirrors `draftPicks.pickNumber`.

Constraints:
- `teams`: unique `(seasonId, captainUserId)` — one team per captain per season
- `teamMembers`: unique `(teamId, userId)` — no duplicate roster entries

## matches.ts — matches

Single table for group stage, tiebreakers, semis, final.

- `stage` enum `match_stage`: `group | tiebreaker | semis | final`
- `state` enum `match_state`: `scheduled | reported | confirmed | disputed`
- `round` int — group stage uses 1..(n-1) from the circle-method round
  index; tiebreakers use **51+**; semis use **101, 102**; final uses **201**. These magic numbers
  are how we sort and distinguish stages without a compound index.
- `winnerTeamId`, `homeScore`, `awayScore`, `reportedBy`, `reportedAt`,
  `confirmedAt` — populated as the match moves through its lifecycle.
  Invariant (code, not DB): a reported/confirmed match has a winner **or**
  is a draw (`winnerTeamId` null, equal non-null scores — Bo2 group only).
- Indexes: on `seasonId`, `homeTeamId`, `awayTeamId`

See [MATCHES.md](MATCHES.md) for the lifecycle and tiebreaker rules.

### match_substitutions (migration `0003_match_substitutions`)

One row per sub request: `matchId`, `teamId` (team the sub plays for),
`subUserId`, `replacedUserId` (roster player sitting out; null = filling an
empty slot), `status` enum `substitution_status`
(`pending | approved | rejected | withdrawn`), `reason`, `requestedBy`,
`decidedBy`, `createdAt`, `decidedAt`. Unique on `(matchId, subUserId)` — a
rejected/withdrawn request for the same player is reused, not duplicated.
Only `approved` rows change a lineup. Lineups are **derived**, not stored:
roster − approved `replacedUserId` + approved `subUserId`.

## stats.ts — accountLinks, riotStatSnapshots, leetifyStatSnapshots

### `accountLinks`
Unique on `(userId, provider, externalId)` (`account_links_user_provider_external_uniq`,
since the pre-squash migration 0008). Provider is enum `account_provider`:
`riot | steam | leetify`.

- **Riot**: up to `MAX_RIOT_ACCOUNTS = 3` links per user
  (`src/app/profile/constants.ts`, enforced in `linkRiotAccount`). The
  same PUUID can't be linked twice by one user.
- **Steam / Leetify**: app code keeps one per user (update-in-place in
  `linkCs2Account`), but the DB would allow more.
- `externalId` — PUUID for riot, Steam64 (`7656…`, 17 digits) for steam,
  profile URL for leetify
- `externalHandle` — `gameName#tagLine` for riot, URL for leetify, null for steam

### `riotStatSnapshots`
Keyed per **account link** (`accountLinkId` FK → `account_links`, cascade)
as well as `userId`. **Replace-on-refresh per link**: `refreshRiotLink` in
`src/lib/stat-refresh.ts` deletes that link's rows and inserts fresh ones —
up to two (solo + flex), never accumulating history. If the Riot rank call
fails (`null`), the existing rows are left untouched.

If the Riot API returns no ranked entries, we insert a single placeholder
row with queue `"solo"` and all rank fields null — that's how we
distinguish "unranked" from "never refreshed".

Consumers that want "a user's rank" (draft pool, home page signups, player
directory, available subs / sub picker) filter `queue = 'solo'` by `userId`
and reduce with `bestRankPerUser` (`src/lib/rank.ts`), so a player with
several linked accounts shows their **highest** rank, not the latest or an
arbitrary one.

- `topChamps` jsonb — `[{ championId, championPoints, championLevel }]`

### `leetifyStatSnapshots`
Scaffolded, **not populated** by any code path. Placeholder for future CS2
stats integration.

## ten-mans.ts — 10-man pickup matches

Five tables: `ten_mans`, `ten_man_signups`, `ten_man_votes`,
`ten_man_captains`, `ten_man_picks`, plus enum `ten_man_state`
(`signups | voting | drafting | ready | complete | cancelled`). Fully
independent of seasons/teams/matches. Constraints, lifecycle and the
"one active at a time" partial unique index are documented in
[TEN-MAN.md](TEN-MAN.md).

## Cascade semantics

Most FKs use `onDelete: "cascade"` so deleting a user or a season wipes
their derived rows. Exceptions:

- `seasons.createdBy` → set null
- `matches.winnerTeamId` → set null
- `matches.reportedBy` → set null
- `ten_mans.createdBy`, `ten_mans.winnerCaptainUserId` → set null (both
  nullable since `0001_reconcile_live_schema`).

Deleting a **user** cascades to sessions, accounts, signups, captains, team
memberships, teams they captain (and therefore those teams' matches), draft
picks (both as captain AND as picked), 10-man signups/votes/captaincies/
picks, account links and stat snapshots. Removing a player's 10-man picks
leaves gaps in that session's pick numbers — acceptable for history.
There is no user-delete UI. Don't delete users without thinking through
season and 10-man state.

## Invariants enforced in code, not DB

- Team size = 5 (captain + 4 picks). Enforced by `finalizeDraft` only
  running when `picks.length === totalPicks(captains.length)`.
- Captain cannot be picked. Enforced in `submitPick` in
  `src/app/seasons/[slug]/draft/actions.ts`.
- Match reporter must be on the home or away team — captain **or**
  rostered member — or an admin. Enforced in `reportMatch` via
  `getTeamForCaptain` (which, despite the name, also matches team members).
- Only one active draft per season. Enforced by `drafts.seasonId` being
  unique.
- Signups only accept users whose username is non-null. Enforced by
  `requireOnboarded()`.
- Max 3 Riot links per user. Enforced in `linkRiotAccount`.
- 10-man invariants (10 signups, 2 captains, 8 picks) — enforced in
  `src/app/10-man/actions.ts`; see [TEN-MAN.md](TEN-MAN.md).

## Where to look when…

- …a query types wrong → run `npm run db:generate` and check the inferred
  types on `*$inferSelect` at the bottom of the schema file.
- …you need a migration → `npm run db:generate` (after schema edit), then
  `npm run db:migrate`. Never edit existing `drizzle/*.sql` files. See
  "Migrations" above.
- …a cascade surprises you → it's listed on the FK in the schema file.
- …a "unique constraint violation" happens → grep the schema for
  `unique(` — the named constraint string is what Postgres will report.
